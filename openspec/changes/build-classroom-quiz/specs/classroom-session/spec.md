# Spec Delta

## Purpose

讓教師掌握一場搶答的開場與截止，讓學生可以從不同裝置加入同一組。重新連線或另開一場後，所有操作仍能對應到原來的活動、組別與權限。

## ADDED Requirements

### Requirement: 教師建場與受限管理

系統 SHALL 以帳號密碼驗證教師後才允許建立及管理其活動，並由教師公告該場活動加入碼。每次管理、加入、查詢、提交都須核對身分、場次及操作權限。（第 3、39 題）

#### Scenario: 登入成功與登入失敗
- **WHEN** 教師分別以正確與錯誤密碼登入
- **THEN** 前者可進入管理頁、建立準備中的活動並取得加入碼；後者不能取得可管理活動的工作階段。

#### Scenario: 學生使用教師操作或冒用其他組別
- **WHEN** 學生要求監看、開場、截止或回寫，或以自己的工作階段指定他組查詢、送答
- **THEN** 系統拒絕未授權操作，不提供受限資料，活動及提交紀錄維持原狀。

### Requirement: 建組加入及身分恢復

系統 SHALL 在準備中及開放中允許學生以活動加入碼進場，由組長以學號建組，依建組順序配置公開代號，另發隨機組內加入碼供組員加入。已提交資料永遠隸屬原活動與原組。（第 3、13、14 題）

#### Scenario: 兩組依序成立
- **WHEN** 兩位組長在同場依序輸入學號建組，第三位學生以第二組的組內加入碼加入
- **THEN** 教師可對照兩個依序分配的公開組別代號及組長學號；第三位學生與第二組共用作答資格。無效的加入碼不授予身分。

#### Scenario: 同一組長重送建組
- **WHEN** 同場同一組長在已驗證的原工作階段重送建組，包含兩次請求並發
- **THEN** 僅成立一組，回覆原組的公開代號；教師監看總組數只增加一次，下一公開代號不被耗用。

#### Scenario: 開放中新建組及晚到組員
- **GIVEN** 活動已開場，教師監看顯示兩組
- **WHEN** 新組長以學號建組，晚到組員再以該組的組內碼加入
- **THEN** 建組成功即取得第三個公開代號，教師監看總組數由 2 增至 3；加入既有組沿用同一代號，總數維持 3。組員只能送出該組仍可答的題目。

#### Scenario: 截止後恢復原組
- **WHEN** 場次已結束，組員以原場次及有效組內碼恢復身分，另有學生嘗試新建組
- **THEN** 原組可查原收件及獲准公開的結果，不能送新答；拒絕新建組。既有公開代號與最終組數均不變。

#### Scenario: 重新進入活動
- **WHEN** 組員重整、重新開頁或斷線重連，工作階段失效時以原場次及組內加入碼重新加入
- **THEN** 恢復原組已提交的題號與答案；切換組別不搬移舊提交。未送出的草稿可隨關頁消失。

### Requirement: 整場活動階段

系統 SHALL 在準備中允許加入與等待，在教師確認有效匯入後一次開放所有單題，並以一次截止結束整場。相同操作重複執行回覆目前階段；已結束場次不可重開。（第 1、2、12、15、16、36、39 題）

#### Scenario: 全份同時開放，各題獨立作答
- **WHEN** 教師開場，甲先提交第 3 題而第 1 題尚有草稿
- **THEN** 每題各有送出操作；該次只提交第 3 題，第 1 題的草稿與順位均不變。重複開場不清除已接受的答案。

#### Scenario: 新舊場次隔離
- **WHEN** 教師連按截止、嘗試重開，之後以同表另建新場；舊場頁面在新場開放時仍送出新答
- **THEN** 舊場只結算一次，回覆舊場已截止。新場的提交、順位及勝組獨立計算，舊頁不能增加新場紀錄。
