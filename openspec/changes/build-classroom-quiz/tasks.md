# Tasks

以下任務留待 Apply。開始前核對使用者對當前提案版本與範圍的明確核准，依專案流程記錄於本變更的 review.md；範圍實質變更須重新送審。每次進入 Apply 前，在儲存庫根目錄執行 `openspec validate build-classroom-quiz --type change --strict`，並核對 `openspec/changes/build-classroom-quiz/specs/` 下 classroom-session、guided-notes-import、quiz-adjudication、classroom-results、guided-notes-writeback 各有一份 `<能力>/spec.md`。這是提案結構檢查，行為驗收見各項任務。

## 1. 應用骨架與持久層

- [x] 1.1 建立 TypeScript 的 Vue 3／HTML／CSS 前端與 Node.js／Fastify 後端，配置 Vitest、Playwright 與本機啟動方式。依文件從乾淨環境啟動並執行型別檢查，記錄外部套件、資料與程式碼來源及授權。
- [x] 1.2 建立 SQLite 結構與交易：活動、組別、版本、題目、有效提交、收件序、結果與回寫進度。以暫存資料檔驗證外鍵、同場同組同題唯一鍵、題內順位唯一鍵及回滾。

## 2. 身分與場次（classroom-session）

- [x] 2.1 建立教師帳密登入、工作階段與管理頁建場流程。測正確、錯誤密碼及學生直接操作教師 API，核對資料授權與場次歸屬。
- [x] 2.2 建立活動碼進場、組長學號建組、公開代號配置及隨機組內碼加入。在準備中測兩組依序成立、同一組長並發或重複建組、無效碼、跨裝置入組及偽填他組身分。重送只留一組及原代號，不消耗下一代號；加入與重新加入都不增加總組數。
- [x] 2.3 實作活動階段、重複操作與獨立新場；開放中已有兩組時新建第三組，核對下一公開代號及教師總組數 2 → 3；晚到組員加入第三組後仍為 3。截止後拒絕新建組，恢復原組只能查原收件及公開結果，核對原代號、總數及有效筆數。以同表兩場和舊頁驗證不可重開、舊場送答不進新場。

## 3. 工作表匯入（guided-notes-import）

- [x] 3.1 建立後端 Google 授權與 Sheets 讀取介面、教師貼網址選分頁及預覽畫面；從空 SQLite 與未授權的瀏覽器依操作文件初始化教師（憑證從環境安全提供）、登入、配置 Google OAuth 用戶端與回呼網址並授權專用測試帳號。先驗證未授權不能讀取，授權後用同簿兩分頁核對穩定識別碼、表名、分頁名、題數及原題號。
- [x] 3.2 辨識四表頭、合併範圍、正整數題號及可比對題目特徵。以六題範例、移欄、空列、缺欄、缺號、全形重號、多表格、受保護及唯讀案例驗證預覽；比對工作表檢查前後未被修改。將四欄母版、權限設定及下列案例預期一併納入版本控制，每個變體只變動指定條件。

  | 資料樣本（同一範本版本） | 預期匯入與開場結果 |
  |---|---|
  | 正例：題號、題目、作答、搶答勝組四欄；六道單題間夾說明列及格式空列 | 成功，保留六個原題號及原順序，可開場。說明列不計題。 |
  | 移動欄位並保留合併範圍；原簿另有一合規分頁 | 所選分頁仍匯入六題，核對兩個現行目標，不混入另一頁。 |
  | 移除「搶答勝組」欄 | 指出缺少該表頭，不可開場，不自動補欄。 |
  | 同頁同時有兩個完整題表 | 指出表格不唯一，禁止靜默選表或開場。 |
  | 同一份表出現數值 1 與文字「０１」 | 指出兩列題號重複，不可開場。 |
  | 一道題目列有題目及作答位置但缺號 | 整份拒用，指出缺號列，不可開場。 |
  | 題組：一個主題號跨兩個子題作答位置 | 提示題組無法唯一對應單題，不拆題，不可開場。 |
  | 教師可讀但不可寫的分頁 | 預覽提示權限不足，不可開場，不試寫。 |
  | 可編輯分頁，但已知一題的勝組格受保護且教師無寫權 | 指出該題及勝組格，不可開場；檢查前後原值均相同。 |

- [x] 3.3 實作成功版本取代、失敗保留但須重選、開場鎖題。測兩次匯入不累加、錯版不可開場，並核對原文字不進入學生草稿。

## 4. 收件、裁決與復原（quiz-adjudication）

- [x] 4.1 在完整請求入口為開場、送答與截止建立同一序列。Vitest 啟動實際 Fastify HTTP 服務，從兩條連線分段送本文，令首段與末段抵達順序相反，並延後較早完整事件的驗證。控制伺服器收件順序後再放行，不依賴 sleep。以無其他答案的新場次各測：送答先於開場 → 拒收、最終 0 筆無勝組；開場先於送答 → 1 筆、該組第一且勝；送答先於截止 → 1 筆、該組第一且勝；截止先於送答 → 拒收、0 筆無勝組。另測兩組答案分段競送為 2 筆、先完整者第一並獲勝；真正並發依該次收件序核對。
- [x] 4.2 實作答案正規化、首次有效提交及同交易保存答案與順位。以全形空白、含首尾空格與換行、答錯但先到、無效身分、無效題號及同組雙裝置競送驗證筆數、原文與收件結果。
- [x] 4.3 建立原收據查詢與截止結算。模擬回應遺失後同文重送、異文重送、截止後重查與重啟 SQLite，驗證原順位、勝組與他題進度均可重現。

## 5. 監看、階段同步及逐題公布（classroom-results）

- [x] 5.1 建立教師各題總覽、組別明細與學生專屬回應；檢查開放期間的 API 及畫面，確認只有教師能取各組答案、已答組數與順位，學生收據也不洩漏全域序號。
- [x] 5.2 實作學生等待、逐題送答與每秒短輪詢，將重連、過時回覆及未送草稿列入測試。以獨立 Playwright 情境分別量測開場成功至學生可答、截止成功至學生鎖定並看見結果，兩者在正常本機環境均須於 2 秒內。
- [x] 5.3 建立教師結算頁及學生逐題結果。以兩題、一組有效或零組有效的資料測試：截止只公開勝組，預覽不公布，單題確認後才公開其勝答；檢查另一題及學生實收資料。分兩場測：（一）預覽後人工改一格，確認被拒，學生只見勝組、教師見衝突、兩格保留當前值；（二）確認成功後注入 Google 整批拒寫，學生見勝答、教師見失敗、原表兩格仍空白。

## 6. 雙格確認與工作表回寫（guided-notes-writeback）

- [x] 6.1 實作同題兩格預覽與正式寫前重定位。用移欄、插列、排序、合併、刪題、同號換題及另一分頁同題測試，驗證原位置與歧義位置均不被誤寫。
- [x] 6.2 實作逐格覆蓋同意、本地公布與待寫工作交易、雙格字串寫入及讀回判定。測試公式（含顯示空白／相同）、不同原值、`001`、`=1+1`、無勝組保留上場兩格；依 5.3 的兩個案例核對公布時間、待寫工作及兩格。逐一比對型別、整格格式、合併範圍及非目標格；加入目標格含部分粗體與內嵌連結的樣本，保留非目標格富文字，目標舊文字的局部樣式不列入通過條件。
- [x] 6.3 實作逐題進度與可重入的失敗重試。以 Vitest 注入撤權、重複確認、後端中斷及已寫但回應逾時；測讀回兩格皆符合、僅一格符合及有新衝突，每次重試核對重新定位所得兩格的原值、型別、跨場寫入版本及逐格覆蓋同意。測 A 逾時、B 寫入同分頁重疊目標、A 恢復：顯示衝突，重新確認前 A 寫入 0 次、B 兩格原樣。包含只重疊一格及另一場寫成相同文字的變體。另測無跨場改寫時後端重啟、兩格讀回皆相符，直接結案且新增寫入 0 次。以上均不重判或撤銷公布。
- [x] 6.4 使用與 7.1 相同版本的四欄資料及重置清單，從母版建立專用真實 Google Sheets 副本、套用並核對授權與保護範圍。完成一次匯入、預覽、確認、讀回與重試，記錄兩格實際位置、型別、原文與其餘格比對結果。將 Google 授權、SQLite 持久目錄及重啟復原方式記入操作文件並依文件重做。
