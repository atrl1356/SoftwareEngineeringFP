# Spec Delta

## MODIFIED Requirements

### Requirement: 整場公布勝組與逐題公布勝答

系統 SHALL 在整場截止後，對新建立場次公開各題勝組名稱，並讓教師可見組名、公開代號、最終有效順位與勝答；遷移前既有場次維持公開代號。教師確認某題前，學生不得取得系統公布的該題勝答；確認後即公布，與雲端回寫成功與否獨立。（第 5、28、29、34、37 題）

#### Scenario: 確認前預覽已過期
- **GIVEN** 該題勝答尚未公布，預覽後有人更改勝組格原值
- **WHEN** 教師持舊預覽按確認，系統在受理確認前讀回兩格並發現變更
- **THEN** 拒絕確認，教師見「需確認衝突」及最新兩格；原表保留兩格當前值，沒有待寫工作。學生仍只見勝組，回應不含系統勝答。

#### Scenario: 確認已成功但 Google 拒絕寫入
- **GIVEN** 兩格均空白，教師確認通過，該題已公布並建立待寫工作
- **WHEN** Google 因撤權拒絕整批更新
- **THEN** 教師見寫入失敗可重試；學生實際取得該題勝答，另一未確認題仍只見勝組；原表兩格仍空白。

#### Scenario: 只確認兩題中的一題
- **WHEN** 教師先預覽甲題、乙題，然後只確認甲題，甲題寫入失敗
- **THEN** 預覽不公布勝答；確認後學生可見甲題勝答，乙題仍只公布勝組，學生保有自己的收件內容。教師可見甲題寫入失敗並重試。公開結果不帶活動加入碼、組內加入碼或組長學號。

#### Scenario: 單一有效組及無勝組
- **WHEN** 一題僅有一組有效提交，另一題全數無效或無人提交
- **THEN** 前題該組勝出，可依一般流程公布與回寫；後題教師與學生均見「無有效作答／無勝組」，教師預覽為「略過」。

#### Scenario: 公開名稱與歷史相容
- **WHEN** 新場次與升級前既有場次各自截止
- **THEN** 新場次的教師與學生結果顯示勝組名稱；既有場次繼續顯示原 G 代號，兩者都不洩漏組內碼或組長學號。
