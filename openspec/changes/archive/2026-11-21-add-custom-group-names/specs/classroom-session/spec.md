# Spec Delta

## MODIFIED Requirements

### Requirement: 建組加入及身分恢復

系統 SHALL 在可供學生進入的準備中及開放中活動允許學生以活動加入碼進場，由組長以符合學號規則及組名規則的值建組。組名去除首尾空白後須為 1–20 個字元、不得含換行或控制字元，且同一活動內唯一；系統依建組順序配置不可指定的公開代號並發組內加入碼。已提交資料永遠隸屬原活動與原組；重送或重新加入不得覆寫組名。僅新建組適用新格式。（第 3、13、14、46、47、49 題）

#### Scenario: 兩組依序成立
- **WHEN** 兩位組長在同場依序輸入學號與有效組名建組，第三位學生以第二組的組內加入碼加入
- **THEN** 教師可對照兩個依序分配的公開組別代號、組名及組長學號；第三位學生與第二組共用作答資格。無效的加入碼不授予身分。

#### Scenario: 同一組長重送建組
- **WHEN** 同場同一組長在已驗證的原工作階段重送建組，包含兩次請求並發
- **THEN** 僅成立一組，回覆原組的組名及公開代號；教師監看總組數只增加一次，下一公開代號不被耗用。

#### Scenario: 開放中新建組及晚到組員
- **GIVEN** 活動已開場，教師監看顯示兩組
- **WHEN** 新組長以學號及有效組名建組，晚到組員再以該組的組內碼加入
- **THEN** 建組成功即取得第三個公開代號，教師監看總組數由 2 增至 3；加入既有組沿用同一組名及代號，總數維持 3。組員只能送出該組仍可答的題目。

#### Scenario: 截止後恢復原組
- **WHEN** 學生可進入的場次已結束，組員以原場次及有效組內碼恢復身分，另有學生嘗試新建組
- **THEN** 原組可查原收件及獲准公開的結果，不能送新答；拒絕新建組。既有組名、公開代號與最終組數均不變。

#### Scenario: 重新進入活動
- **WHEN** 在准許學生查閱的場次，組員重整、重新開頁或斷線重連，工作階段失效時以原場次及組內加入碼重新加入
- **THEN** 恢復原組已提交的題號、答案與組名；切換組別不搬移舊提交。未送出的草稿可隨關頁消失。

#### Scenario: 新學號正反例與舊名冊
- **WHEN** 在準備中及開放中，分別從學生頁或直接請求用「 123456789 」、首碼 0 或 2、全形數字、內部空白、含字母、八位或十位學號新建組
- **THEN** 只有合法值成立一組，以字串保存修整後的學號。拒絕不占組數或下一公開代號，舊名冊中的「101」原樣保留。已驗證原組長可重查原組，組員憑有效組內碼恢復。只知道舊學號不能冒領原組，也不能在新場新建組。

#### Scenario: 已結束還原後以原兩碼重新加入
- **GIVEN** 甲、乙在截止前都曾送答，移除期間原碼與舊身分均無法使用
- **WHEN** 原教師還原，甲持原活動碼與甲的原組內碼重新加入，另以原活動碼配錯誤組內碼及舊工作階段查詢
- **THEN** 重新加入成功者取得甲的原收據、各題勝組與已公布的勝答。錯誤組內碼及舊工作階段不能取得結果。甲無法查看乙的私人收據、完整順位，也無法新建組或送新答。

#### Scenario: 同名與無效名稱
- **WHEN** 兩組以修整後相同名稱建組，或輸入空白、超過 20 字元、換行或控制字元
- **THEN** 僅第一組成立；後續請求被拒且不增加組數或耗用公開代號。

#### Scenario: 重送與重新加入
- **WHEN** 原組長重送相同建組請求，或組員以組內碼重新加入
- **THEN** 系統回傳既有組名與公開代號，原提交、順位及名稱均不改變。
