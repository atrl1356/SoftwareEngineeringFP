Apply 前核對使用者對本提案版本與範圍的明確核准，依專案流程記錄審查依據。執行 `openspec validate build-classroom-quiz-update --type change --strict`。下列核取方塊在實作及該項驗收通過後勾選。

## 1. 現有 SQLite 資料與工作復原

- [x] 1.1 增加移除時間、生命週期版本、到期掃描索引、可重試的操作與回寫工作紀錄。以含舊學號、收據、待核實題及共用分頁的舊資料庫執行升級、重啟、再次升級，核對外鍵、組數、原碼、已公布結果與原進度。
- [x] 1.2 在確認及重試加入分頁佇列前登記本場版本與工作，完成或失敗時一併保存題目進度。Vitest 分別暫停排隊、外部寫入與讀回，檢查待移除資格。模擬重啟，區分未獲同意、已公布待核實、失敗與已結案，確保未知結果先核對兩格。

## 2. 單場、批次與存取撤銷

- [x] 2.1 加入原教師的兩份活動清單、逐場資格及共用的移除操作。在 Vitest 測準備中有等待組、開放中、所有已結束題目組合（含全題略過）、他人或不存在的 ID、混選、全部不符、重複 ID。逐場比對授權、原因與資料未外洩。
- [x] 2.2 在短交易內重查所有權、階段、逐題進度及工作，記錄版本與移除結果。控制開場、送答、截止、回寫登記和移除先後，檢查第 45 題兩種生效順序及原順位。注入單場失敗、批次中斷與回覆遺失，重送不延長期限，其他場次可核對。
- [x] 2.3 在教師列表加入單列操作、多選、確認與逐場結果。用 Playwright 準備同名不同碼及混合四場，查核第 43 題的欄位與提示，取消時攔截移除請求應為零。確認期間令一場先開場，核對畫面逐場更新且略過原因可見。
- [x] 2.4 將活動碼、組內碼、活動快照、收據及同文重送的存取檢查放在回傳資料之前。Playwright 使用等待及已結束的舊學生頁，觀察終止後清除畫面、停止發請求、返回入口，延遲的成功回覆不能復活畫面。Vitest 對舊碼、舊憑證、不同原文及新答案直接呼叫 API，核對無資料、無新增提交。另測暫時斷線可重連及其他場登入仍有效。
- [x] 2.5 在匯入、重選及預覽讀取完成時核對活動版本。Vitest 暫停讀取，分別於移除後及移除再還原後放行。驗證舊作業不改變題目、可開場旗標與預覽，也不產生外部寫入。

## 3. 還原、清除與共用試算表

- [x] 3.1 實作原教師的「已移除」入口與單場還原。準備中場次換發全部碼，由原教師依公開代號分送。Vitest 以兩組、舊工作階段、碰撞碼及故障注入驗證全數換發或全數回滾。Playwright 以教師及兩組查新舊碼、原代號及組數，核對其他教師與學生均無法取得整份新碼名單。
- [x] 3.2 對已結束還原場次沿用原活動碼及各組原碼，只開放學生重新驗證後讀取。教師、甲、乙用分開的瀏覽器查回原紀錄，核對私有收據、公開勝組及已公布勝答的可見範圍。用 API 測舊憑證、缺組內碼、錯碼、新建組與送新答均被拒絕，無新增順位或回寫。對兩種還原都重送先前的還原及移除操作，核對碼與狀態。
- [x] 3.3 實作啟動補清與運行中自動清理，在還原與清理交易內比較同一伺服器期限。使用可控時鐘及實體暫存 SQLite 測到期前一毫秒、恰好 240 小時、掃描延遲、並發還原、停機跨期與清除半途失敗。逐表驗證整筆回滾或清除完成，教師授權、其他場次、共用版本與全域收件序完好。
- [x] 3.4 以可重置的 Sheets 替身驗證 A 完成後，B 的舊預覽只重疊一格且兩場文字相同。覆蓋 A 移除、重啟後重送舊工作、期限內還原及另一次到期清除。逐段比對外部寫入次數為零、表格快照一致、B 仍需重新確認。把分碼、還原資格及到期時間補入 README 並依說明重做兩種還原。

## 4. 建組學號與開場確認

- [x] 4.1 更新學生輸入與後端新建組驗證。Vitest 與 Playwright 覆蓋準備中及開放中、合法九位首碼 1、首尾空白、其他首碼、全形、字母、內部空白、空值、八與十位。拒絕時不增加組數或占用代號。測舊學號名冊、原組長重送、組員用碼恢復及跨場不能藉舊學號建組。
- [x] 4.2 在原完整收件順序內判斷組數、核發並核對零組開場確認。在真實 Fastify HTTP 的 Vitest 測試中，零組提示期間成立第一組，用兩條連線分段送答及正式確認，延後先完整事件的驗證。交換到達順序，核對前者拒收時有效筆數為零，確認先生效則首筆有效答案第一且勝出。確認後重送不重開，舊憑據不能跨活動、還原或匯入版本使用。
- [x] 4.3 教師頁依後端回覆顯示第 48 題的確認文字。Playwright 分開測只有進場者時取消或確認、提示期間建組、畫面零組但後端已有一組時單擊、提示後匯入失效或活動移除。記錄正式開場到學生頁自動更新在兩秒內，另測截止同步兩秒。依實際畫面更新 README 中的學號及開場說明。

## Apply 驗收紀錄

以合併提案的 `main`（`2fe4890`）及第一輪資料結構為基準。測試環境為 Node.js 24.22.1、SQLite、Chromium 156 與每案可重置的 Guided Notes v1 替身。瀏覽器分開保存原教師、其他教師與學生組別的工作階段。新舊 SQLite、跨場共用表及瀏覽器案例可分別重跑。[資料與交易測試](../../../tests/retention.test.ts) · [舊版資料結構](../../../tests/fixtures/classroom-v1.sql) · [真實 HTTP 測試](../../../tests/ordering.test.ts) · [瀏覽器驗收](../../../tests/retention.e2e.ts)

### 第 49 題的逐項對照

| 情境（依原題順序） | 驗收結果 | 工具 |
| --- | --- | --- |
| 1. 同名活動 | 取消發出 0 次移除請求。逐場確認後只有所選 ID 進入已移除清單，同名另一場留在原列表。 | Playwright |
| 2. 批次移除 | 準備中與全題結案的場次成功移除。開放中、回寫失敗，以及確認期間才開場的活動各自保留並列出原因。 | Vitest、Playwright |
| 3. 所有權與重送 | 他人與不存在的 ID 得到相同的拒絕結果。學生無法操作管理入口。部分交易提交後重開資料庫重送，第一場的期限維持原值。 | Vitest、Playwright |
| 4. 移除資格 | 開放中拒絕移除。截止保留原順位。逐題檢查結案、略過及排隊、外部寫入或讀回中的工作。 | Vitest |
| 5. 舊頁與收據 | 等待頁和結果頁返回加入入口。遲到的成功回覆不能復活舊畫面。舊身分的收據與重送皆遭拒絕。 | Vitest、Playwright |
| 6. 跨場共用表 | B 預覽 C、D 後 A 寫 C、E，重疊格的預計文字相同。A 移除、重啟、重送舊工作、還原及到期清除後，表格一致、額外寫入 0 次，B 舊預覽仍須重新確認。 | Vitest、Sheets 替身 |
| 7. 兩種還原 | 準備中還原同一名冊與公開代號，原教師分送換發的兩組新碼。已結束沿用原兩碼重新登入，保留原順位與逐題進度。舊工作階段仍失效，重送還原或舊移除均不改結果。 | Vitest、Playwright |
| 8. 還原期限 | 到期前 1 毫秒可還原，恰好 240 小時即拒絕。驗證清理與還原交錯、失敗整場回滾、運行時掃描與停機後補清，保留全域收件序和跨場版本。 | Vitest、暫存 SQLite |
| 9. 學號與舊資料 | 新建組僅接受去除首尾空白後符合 `^1[0-9]{8}$` 的字串。錯誤輸入不占組別代號。第一輪短學號與舊組內碼可查回原組。 | Vitest、Playwright |
| 10. 零組提示 | 只輸入活動碼仍須確認，取消維持準備中。提示期間可建組。兩條真實 HTTP 連線交換正式開場與答案的完整收件順序，僅開場後的答覆生效。 | Vitest、Playwright |
| 11. 畫面落後與匯入失效 | 畫面顯示零組、後端已有組時單擊即開場。學生自動更新。匯入失效後的舊確認維持準備中。 | Vitest、Playwright |

第 37 題重跑原教師、甲、乙三個工作階段。甲先送空白、乙送 `CPU`、甲補答、乙重送，最後僅兩筆有效且乙第一。學生截止先見勝組，逐題確認後才可見勝答。讀回 C3 為文字 `CPU`、D3 為文字 `G02`，其餘格一致。[第 37 題與同步量測](../../../tests/classroom.e2e.ts)
