# Spec Delta

## Purpose

讓原教師能辨認並整理自己建立的場次，在期限內取回名冊與結算，同時讓等待中的學生明確知道何時已無法進入，並讓仍需回寫學習單的場次保有完成工作的機會。

## ADDED Requirements

### Requirement: 教師依活動 ID 確認移除

系統 SHALL 在「我的活動」提供逐列移除及勾選多場移除。依已登入的教師及活動 ID 判斷權限，確認視窗逐場顯示名稱、活動碼與目前階段，說明「學生將無法再進入，活動紀錄會保留」及十天期限。（第 39、43、49 題）

#### Scenario: 同名場次與取消

- **GIVEN** 教師有兩場同名但活動碼不同的場次，其中一場有兩組等待
- **WHEN** 教師開啟單場移除視窗後取消，再只確認有兩組等待的場次
- **THEN** 取消時停在原列表、移除請求為零。確認後只有該 ID 從「我的活動」移到原教師的「已移除」，另一場仍可使用。

#### Scenario: 混選與確認期間資格改變

- **GIVEN** 勾選一場準備中、一場開放中、一場已結束但回寫失敗、一場已結束且全題結案
- **WHEN** 教師核對哪些場次可移除、哪些須略過及原因，再按確認
- **THEN** 只有第一、四場移除。第二場繼續搶答，第三場仍可重試，教師取得逐場結果。若第一場先開場，確認時也略過。若原先列為略過的場次變為合格，須另行確認。
- **AND** 全部不符時提示原因，活動列表與紀錄維持原狀。

#### Scenario: 越權或重複指定

- **WHEN** 學生要求管理活動，或另一教師列出已移除清單、指定他人活動還原、將他人或不存在的 ID 混入含自己活動的批次
- **THEN** 只處理該教師自己有權操作且已確認的項目。同一 ID 至多處理一次，不能從未授權項目的回覆取得場名、階段、組數、回寫或憑證。

### Requirement: 逐場移除資格與重試

系統 SHALL 在移除生效時逐場核對擁有者、場次階段、逐題結案情況與排隊或執行中的回寫。移除和該場的存取失效一起生效，每場可獨立重試。（第 29、34、35、43–45、49 題）

#### Scenario: 三個階段與逐題判定

- **WHEN** 分別移除已有組別的準備中場、開放中場及已結束場
- **THEN** 準備中可移除並保留原組。開放中提示先明確截止。已結束須每個有勝組題均已確認兩格寫入、每個無勝組題均已略過，且沒有該場排隊或執行中的回寫。全場無勝組也可移除。
- **AND** 任一題未確認、待寫、寫入中、僅核實一格、待核實、失敗或有衝突即保留整場，向原教師列出題號及原因。其他場次事後改寫相同位置，不撤銷已保存的結案。

#### Scenario: 開場或截止與移除競爭

- **WHEN** 開場、有效送答、明確截止或移除前後交錯
- **THEN** 開場先生效時拒絕移除。移除先生效時後到的開場、加入與送答不得生效。截止先生效時依已結算題目重新判定，既有有效答案、順位及勝組維持原結果。

#### Scenario: 回覆遺失及單場失敗

- **WHEN** 批次有一場提交失敗，或教師連按、遺失回覆、還原後又重送原移除請求
- **THEN** 失敗場保持原狀，其餘可逐場查核。已移除場回覆原結果，不延長期限。還原後收到過去的移除請求也不再次移除。

### Requirement: 十天內由原教師還原原場次

系統 SHALL 讓原教師在移除成功後未滿 240 小時從「已移除」還原同一場。保留原階段、名冊、公開代號、題目對照、答案、收件序、順位、勝組、公布與雙格回寫進度。準備中還原時由原教師取得並分送換發的新碼。已結束還原時，學生沿用原活動碼及原組內碼重新加入，限查原組收據及獲准公開的結果。（第 14、28、35、45、46、49 題）

#### Scenario: 準備中還原與重送

- **GIVEN** 準備中有兩組等待，已記錄舊碼、組別公開代號、場次與題目
- **WHEN** 原教師還原並因回覆遺失重送同一次還原
- **THEN** 活動回到原教師列表並維持準備中。原教師取得換發的活動碼及依公開組別代號列出的各組新碼，分別交給對應組長。重試取得同一批碼。以新碼可回到各自原組，總數與代號不變。舊活動碼、任一舊組內碼及舊工作階段均無法取得身分。

#### Scenario: 已結束場次還原

- **WHEN** 原教師還原每題均已結案的已結束活動
- **THEN** 原教師可檢視原名冊、答案、順位、勝組與逐題進度。原活動碼及每組原組內碼恢復接受重新加入。學生須重新取得身分才可查本組收據與第 28 題允許的結果。場次仍已結束，沒有重算、重新開場或重啟寫表工作。

### Requirement: 到期自動永久清除

系統 SHALL 以伺服器移除成功時刻加上 240 小時決定期限。到期立即失去還原資格，運行中自動清除，停機跨期則重啟後補清。單場刪除其全部從屬資料應具備原子性。（第 35、44–46、49 題）

#### Scenario: 截止瞬間與排程競爭

- **WHEN** 分別在期限前一毫秒及恰好到期時還原，並讓清理工作同時執行或延遲
- **THEN** 期限內生效的還原完整保留，過期即不能還原。相同活動不能先回覆還原成功又被同一輪清理刪除。

#### Scenario: 清理失敗、停機與重啟

- **WHEN** 清除中途失敗，或服務停機跨過期限後重啟
- **THEN** 失敗時單場整筆回滾，重試完成後場次、加入碼、學生工作階段、名冊、題目對照、提交、順位、結算及回寫明細均不可取回。教師帳號、Google 授權、其他場次、全域收件序及跨場版本仍可使用。
