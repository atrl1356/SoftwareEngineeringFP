# Spec Delta

## MODIFIED Requirements

### Requirement: 建組加入及身分恢復

系統 SHALL 在可供學生進入的準備中及開放中活動允許學生以活動加入碼進場，由組長以去除首尾空白後符合 `1[0-9]{8}` 全字串的學號建組，依建組順序配置公開代號，另發隨機組內加入碼供組員加入。已提交資料永遠隸屬原活動與原組。僅新建組適用新格式。組內碼加入與舊組恢復沿用既有身分驗證。（第 3、13、14、46、47、49 題）

#### Scenario: 兩組依序成立
- **WHEN** 兩位組長在同場依序輸入學號建組，第三位學生以第二組的組內加入碼加入
- **THEN** 教師可對照兩個依序分配的公開組別代號及組長學號；第三位學生與第二組共用作答資格。無效的加入碼不授予身分。

#### Scenario: 同一組長重送建組
- **WHEN** 同場同一組長在已驗證的原工作階段重送建組，包含兩次請求並發
- **THEN** 僅成立一組，回覆原組的公開代號；教師監看總組數只增加一次，下一公開代號不被耗用。

#### Scenario: 開放中新建組及晚到組員
- **GIVEN** 活動已開場，教師監看顯示兩組
- **WHEN** 新組長以學號建組，晚到組員再以該組的組內碼加入
- **THEN** 建組成功即取得第三個公開代號，教師監看總組數由 2 增至 3；加入既有組沿用同一代號，總數維持 3。組員只能送出該組仍可答的題目。

#### Scenario: 截止後恢復原組
- **WHEN** 學生可進入的場次已結束，組員以原場次及有效組內碼恢復身分，另有學生嘗試新建組
- **THEN** 原組可查原收件及獲准公開的結果，不能送新答；拒絕新建組。既有公開代號與最終組數均不變。

#### Scenario: 重新進入活動
- **WHEN** 在准許學生查閱的場次，組員重整、重新開頁或斷線重連，工作階段失效時以原場次及組內加入碼重新加入
- **THEN** 恢復原組已提交的題號與答案；切換組別不搬移舊提交。未送出的草稿可隨關頁消失。

#### Scenario: 新學號正反例與舊名冊

- **WHEN** 在準備中及開放中，分別從學生頁或直接請求用「 123456789 」、首碼 0 或 2、全形數字、內部空白、含字母、八位或十位學號新建組
- **THEN** 只有合法值成立一組，以字串保存修整後的學號。拒絕不占組數或下一公開代號，舊名冊中的「101」原樣保留。已驗證原組長可重查原組，組員憑有效組內碼恢復。只知道舊學號不能冒領原組，也不能在新場新建組。

#### Scenario: 已結束還原後以原兩碼重新加入

- **GIVEN** 甲、乙在截止前都曾送答，移除期間原碼與舊身分均無法使用
- **WHEN** 原教師還原，甲持原活動碼與甲的原組內碼重新加入，另以原活動碼配錯誤組內碼及舊工作階段查詢
- **THEN** 重新加入成功者取得甲的原收據、各題勝組與已公布的勝答。錯誤組內碼及舊工作階段不能取得結果。甲無法查看乙的私人收據、完整順位，也無法新建組或送新答。

### Requirement: 整場活動階段

系統 SHALL 在準備中允許加入與等待，於開場受理時以該場已成立組數判定。有效匯入且至少一組可單擊開場，零組須另行確認後才一次開放所有單題，並以一次截止結束整場。相同操作重複執行回覆目前階段；已結束場次不可重開。（第 1、2、12、15、16、36、39、48、49 題）

#### Scenario: 全份同時開放，各題獨立作答
- **WHEN** 教師開場，甲先提交第 3 題而第 1 題尚有草稿
- **THEN** 每題各有送出操作；該次只提交第 3 題，第 1 題的草稿與順位均不變。重複開場不清除已接受的答案。

#### Scenario: 新舊場次隔離
- **WHEN** 教師連按截止、嘗試重開，之後以同表另建新場；舊場頁面在新場開放時仍送出新答
- **THEN** 舊場只結算一次，回覆舊場已截止。新場的提交、順位及勝組獨立計算，舊頁不能增加新場紀錄。

#### Scenario: 只有進場尚未建組

- **GIVEN** 匯入有效，已有學生輸入活動碼但組數為零
- **WHEN** 原教師首次按開放，再分別測試取消或確認
- **THEN** 第一次顯示「目前尚無組別，仍要開放搶答嗎？」並維持準備中。取消不開場。確認後即使仍是零組也正式開場，學生可晚到建組。

#### Scenario: 提示期間建組與完整送達順序

- **WHEN** 提示期間第一組成立，該組的完整答案先於教師確認到達，另一有效答案在正式開場後到達
- **THEN** 前者回覆尚未開始且不占順位，後者為該題第一筆。人員考慮時間不占收件順序，重送開場不清除答案或重複轉換階段。

#### Scenario: 教師畫面落後或條件改變

- **WHEN** 前端顯示零組但後端已成立一組時單擊開場，或教師在另一場確認前匯入已失效、活動已移除或權限不符
- **THEN** 第一場單擊即開放。其餘拒絕且保留原狀。學生開場同步的兩秒從成功轉換階段起算。
